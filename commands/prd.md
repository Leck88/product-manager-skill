# 命令：/prd

## 触发方式
- `/prd [功能名]`
- "帮我写 PRD"、"写一份产品需求文档"

## 执行步骤

### Step 1：收集必要信息
如果没有足够上下文，先询问：
1. 这个功能要解决什么问题？（Why）
2. 目标用户是谁？（Who）
3. 功能的核心范围是什么？（What）
4. 有什么特殊的技术或业务约束吗？

### Step 2：生成 PRD 草稿
根据收集的信息，按以下结构生成 PRD：

```
1. 背景与目标（业务背景、问题陈述、产品目标、成功指标）
2. 目标用户（Persona 简述、使用场景）
3. 功能规格（功能详情、字段说明、业务规则、异常场景）
4. 验收标准（AC 列表）
5. 非功能需求（性能、安全、兼容性）
6. 数据埋点需求
7. 上线计划
8. 待确认问题
```

### Step 3：标注需要补充的内容
在 PRD 草稿中，用 `[待确认]` 标注需要用户补充或确认的信息。

### Step 4：输出

输出完整 PRD 后，提示：
> "PRD 草稿已生成。建议确认以下事项后组织评审：[列出 [待确认] 项目]"
