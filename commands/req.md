# 命令：/需求

## 触发方式
- `/需求 [描述]`
- 用户说"我有个需求"、"帮我分析一个需求"

## 执行步骤

加载本命令后，按以下步骤执行：

### Step 1：理解需求表述
先重述用户描述的需求，确认理解无误。

### Step 2：5W1H 追问
如果信息不足，依次追问：
1. **Why（为什么）**：这个需求背后真正要解决的问题是什么？
2. **Who（谁）**：哪类用户，在什么场景下？
3. **What（是什么）**：核心问题/痛点是什么？
4. **When（何时）**：使用场景的时间特征？
5. **Where（在哪）**：什么环境下使用？
6. **How（怎样）**：用户期望的解决方式是什么？

> ⚠️ 不要一次抛出所有问题，根据用户描述的信息量，只追问缺失的关键信息。

### Step 3：需求合法性验证
- 用户价值：✅ / ❌ / ⚠️ 需要验证
- 商业价值：✅ / ❌ / ⚠️ 需要验证
- 技术可行性：初步判断

### Step 4：输出需求分析结果

```markdown
## 需求分析结果

**核心问题**：[用户真正要解决的问题]

**目标用户**：[用户角色描述]

**用户故事**：
作为 [用户]，我希望 [功能]，以便 [价值]。

**建议优先级**：P0 / P1 / P2
**理由**：[说明优先级依据]

**功能范围建议**：
- 本次包含：[MVP 功能]
- 后续迭代：[可延后的功能]

**待确认问题**：
- [ ] [问题1]
- [ ] [问题2]
```

### Step 5：询问下一步
> "需求分析完成。需要我帮你写成 PRD 文档吗？用 `/prd [功能名]` 启动。"
