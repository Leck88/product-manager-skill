# 用户故事模板

## 用户故事格式

```
作为 [用户角色]，
我希望能够 [完成某个功能/目标]，
以便 [获得某种价值/解决某个问题]。

验收标准：
- 当 [某个条件] 时，系统应该 [表现某种行为]
- 当 [某个条件] 时，系统应该 [表现某种行为]
```

---

## 用户故事拆分原则（INVEST）

| 原则 | 说明 |
|------|------|
| **I**ndependent（独立）| 故事之间尽量独立，可单独交付 |
| **N**egotiable（可协商）| 细节可以和团队讨论，不是合同 |
| **V**aluable（有价值）| 对用户有明确价值 |
| **E**stimable（可估算）| 研发能评估工作量 |
| **S**mall（小）| 能在一个迭代内完成 |
| **T**estable（可测试）| 验收标准明确可测 |

---

## 故事地图模板

```
用户目标（Why）
    └── 用户活动（What - 大故事）
            ├── 用户任务1（How - 用户故事）
            ├── 用户任务2
            └── 用户任务3
```

## 用户故事示例集

### 示例一：搜索功能

```
作为 一名内容消费用户，
我希望能够 在首页通过关键词搜索内容，
以便 快速找到我感兴趣的文章，而不需要手动翻页。

验收标准：
- 当 我在搜索框输入关键词并按回车时，系统应在 1s 内返回搜索结果
- 当 搜索结果为空时，系统应显示"暂无相关内容，换个关键词试试"
- 当 我清空搜索框时，系统应恢复到搜索前的页面状态
- 搜索词应高亮显示在搜索结果中
```

### 示例二：消息通知

```
作为 一名注册用户，
我希望能够 在有新回复时收到推送通知，
以便 不错过重要的互动，及时回复。

验收标准：
- 当 其他用户回复我的评论时，我应在 5 分钟内收到推送
- 当 我点击推送时，应跳转到对应的评论页面
- 当 我关闭通知权限时，不应收到任何推送
- 当 我在 App 内查看了消息，对应推送应自动消除
```
