# 用户研究能力

## 能力描述

设计和执行用户研究计划，通过定性和定量方法深入理解用户行为、需求和痛点，为产品决策提供可靠的用户洞察。

---

## 研究方法选择

| 方法 | 适用场景 | 输出 |
|------|----------|------|
| 深度访谈 | 探索未知问题、理解动机 | 访谈记录、洞察报告 |
| 问卷调研 | 验证假设、量化规模 | 数据报告 |
| 可用性测试 | 发现体验问题、验证设计 | 问题清单、改进建议 |
| 数据分析 | 了解用户行为规律 | 数据洞察报告 |
| 竞品体验 | 对标市场、找差距 | 竞品分析报告 |
| 焦点小组 | 探索态度、集体讨论 | 讨论记录 |

## 深度访谈指引

### 访谈设计原则
1. **开放式问题为主**：避免是/否的封闭问题
2. **追问行为，不问态度**：问"你上次是怎么做的"，不问"你喜欢哪个"
3. **保持中立**：不要暗示期望答案
4. **聚焦具体情境**：让用户回忆真实发生的事，不是假设

### 访谈提纲结构
```
1. 开场暖场（5分钟）
   - 自我介绍，说明目的
   - 消除紧张感

2. 背景了解（10分钟）
   - 了解用户基本情况、工作/生活背景
   - 与产品相关的使用习惯

3. 核心问题探索（30分钟）
   - 围绕目标话题深入挖掘
   - 5 大核心问题 + 追问

4. 痛点场景还原（10分钟）
   - 请用户回忆一次具体的糟糕体验
   - STAR 法则追问（情境-任务-行动-结果）

5. 收尾（5分钟）
   - 还有什么想补充的？
   - 感谢
```

### 好问题 vs 坏问题

| 坏问题 | 好问题 | 原因 |
|--------|--------|------|
| 你喜欢这个功能吗？ | 你上次用这个功能是什么时候？ | 行为比态度可靠 |
| 你会用这个功能吗？ | 如果有这个功能，你的哪个流程会改变？ | 避免虚假承诺 |
| 这个功能好不好用？ | 你在用这个功能时遇到过什么困难？ | 具体场景下才有效 |

## 用户画像（Persona）建立

### Persona 模板
```markdown
## [角色名称]

**基本信息**
- 年龄：xx 岁
- 职业：xx
- 技术熟练度：高/中/低
- 使用频率：日活/周活

**目标**
- 首要目标：[用这个产品想实现什么]
- 次要目标：[其他相关目标]

**痛点**
- [排列前3个核心痛点]

**行为特征**
- [描述与产品相关的典型行为]

**代表性语录**
> "[一句能代表这类用户的原声话语]"
```

## 用户旅程地图

### 阶段划分
```
[发现] → [考虑] → [决策] → [使用] → [留存] → [推荐]
```

### 每个阶段分析维度
- **用户行为**：用户在做什么
- **用户想法**：用户在想什么
- **用户情绪**：情绪高低（绘制情绪曲线）
- **触点**：用户通过什么渠道接触产品
- **痛点**：有什么障碍或不满
- **机会点**：哪里可以改进

---

## 数据分析方法

### 关键指标体系
```
获取层：DAU/MAU、新增用户数、渠道分布
激活层：注册转化率、新手引导完成率
留存层：次日/7日/30日留存、流失原因
变现层：付费转化率、ARPU、LTV
推荐层：NPS、分享率、口碑传播
```

### 用户分群
- **RFM 模型**：Recency（最近一次）、Frequency（频率）、Monetary（金额）
- **行为分群**：按核心行为路径分类
- **生命周期分群**：新用户/成长用户/成熟用户/流失用户
